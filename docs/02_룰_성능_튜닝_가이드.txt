[샘플 문서] 룰 성능 튜닝 가이드
※ 연습용으로 만든 가상의 문서입니다. 실제 사내 규정이나 제품 사양과 다릅니다.

1. 성능을 볼 때 먼저 확인할 것
룰 수행이 느릴 때는 룰 자체보다 외부 조회를 먼저 의심합니다. 룰 안에서 데이터베이스를 반복 조회하면 건수가 늘수록 응답 시간이 선형으로 증가합니다. 같은 값을 여러 번 조회하지 않도록 한 번 조회한 값을 재사용합니다.

2. 캐시 사용 기준
자주 바뀌지 않는 기준 정보는 캐시에 적재하여 사용합니다. 캐시된 값은 변경이 발생했을 때 갱신되도록 갱신 시점을 명확히 정해야 합니다. 갱신 시점이 불명확하면 오래된 값으로 심사가 이루어지는 문제가 생깁니다.

3. 룰 작성 시 주의사항
조건이 많은 룰은 가장 많이 걸러내는 조건을 앞에 둡니다. 불필요하게 중복된 조건은 제거하고, 하나의 룰이 너무 커지면 여러 개의 하위 룰로 나눕니다.

4. 멀티 스레드 호출
여러 스레드에서 동시에 룰을 호출할 때는 스레드마다 별도의 실행 컨텍스트를 사용하고, 공유되는 캐시는 읽기 전용으로 다루는 것이 안전합니다.

5. 성능 측정 방법
튜닝 전후를 비교하려면 같은 데이터 1,000건으로 세 번 이상 측정하여 평균을 냅니다. 처음 한 번은 캐시가 비어 있어 느리므로 제외합니다.
