[샘플 문서] 배치 호출과 로그 설정
※ 연습용으로 만든 가상의 문서입니다. 실제 사내 규정이나 제품 사양과 다릅니다.

1. 배치에서 룰을 호출하는 방식
대량 건을 처리하는 배치 프로그램은 시작 시점에 초기화를 한 번 수행한 뒤, 건별로 룰을 호출합니다. 건마다 초기화를 다시 하면 처리 시간이 크게 늘어납니다.

2. 로그를 생성하지 않으려면
배치에서 룰 호출 시 로그가 필요 없다면 호출 옵션에서 로그 사용 여부를 끄면 됩니다. 로그를 끄면 처리 속도가 빨라지지만, 장애가 났을 때 원인을 추적하기 어려워집니다. 운영 환경에서는 오류 로그만 남기는 설정을 권장합니다.

3. 로그 보관 기간
로그는 기본적으로 30일간 보관하고, 이후에는 압축하여 별도 저장소로 옮깁니다. 감사가 필요한 프로젝트는 보관 기간을 고객사와 협의하여 조정합니다.

4. 장애 대응 순서
배치 실패 시 먼저 오류 로그의 첫 번째 오류를 확인합니다. 뒤쪽 오류는 첫 오류의 연쇄 결과인 경우가 많습니다. 원인을 확인한 뒤 실패한 건만 재처리합니다.
